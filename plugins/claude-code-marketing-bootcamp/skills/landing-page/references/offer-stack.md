# Offer Stack

The page sells the offer, not the page. Build the offer first.

Walk the user through each slot. Fill it with their real product details from `landing-page-brief.md` — never generic placeholders.

## The Stack

1. **Core promise** — one sentence. The single transformation the buyer gets.
   *Test:* could a stranger repeat it back? If not, it's too vague.

2. **Who it's for / who it's NOT for** — naming the non-buyer makes the buyer feel seen.

3. **Deliverables** — the concrete things they receive (modules, calls, templates, the asset). Tangible nouns, not adjectives.

4. **Stack + value framing** — list each component with the value it carries. The perceived value of the parts should clearly exceed the price.

5. **Price + justification** — the number, and the one-line reason it's worth more than the number (time saved, outcome value, cost of not having it).

6. **Risk reversal** — guarantee, refund window, or "try the first module free." Removes the last hesitation.

7. **Bonus** (optional) — one well-chosen fast-action bonus beats three weak ones. Tie it to speed or to the core outcome.

8. **The CTA** — exactly one action, phrased as a verb the buyer takes:
   "Get the [asset]" / "Join the cohort" / "Start the free module".
   Not "Submit", not "Learn more", not two competing buttons.

## Lead-magnet variant

For a free lead magnet, collapse to: core promise → what's in it → who it's for → one CTA ("Get the [asset]"). No price, no guarantee, no stack. The email *is* the price.

## Output format

Produce a single block the user approves before any copy is written:

```
OFFER STACK
Promise:      ...
For:          ...   | Not for: ...
Deliverables: ...
Stack:        - item — value
Price:        $X — because ...
Risk reversal: ...
Bonus:        ...
CTA:          "..."
```
